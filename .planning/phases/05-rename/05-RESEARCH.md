# Phase 5: Rename - Research

**Researched:** 2026-05-17
**Domain:** TypeScript MCP server rename — package, binaries, env vars, tool names, documentation
**Confidence:** HIGH

## Summary

Phase 5 renames the Prefect package to Legate across all surfaces: package identity (`@momidala/prefect` → `@momidala/legate`), CLI binaries (`prefect`/`prefect-mcp` → `legate`/`legate-mcp`), 40 MCP tool names (`prefect_*` → `legate_*`), 7 environment variables (`PREFECT_*` → `LEGATE_*`), the MCP server registration name in `McpServer({ name: 'prefect' })`, and all user-facing documentation. Existing `PREFECT_*` users get a one-time deprecation warning per variable but the server still connects.

The `~/.config/prefect/` runtime directory (holding `servers.json` and `sessions.json`) is explicitly **out of scope** — it must remain unchanged to avoid breaking existing sessions. This is the only runtime state concern.

The rename pattern is already established in the codebase: `OPENCODE_*` vars were previously deprecated in favor of `PREFECT_*` using module-level warning flags and lazy evaluation IIFEs. The same pattern applies identically for `PREFECT_*` → `LEGATE_*`.

**Primary recommendation:** Execute the rename in three distinct passes — (1) `package.json` + `src/` code (source rename), (2) test files (test rename), (3) documentation (doc rename). Build and test between passes to catch compilation errors early.

### Deprecation Warning Pattern

The existing `OPENCODE_*` → `PREFECT_*` deprecation pattern (already in the codebase) must be replicated exactly for `PREFECT_*` → `LEGATE_*`:

```typescript
// VERIFIED: src/auth.ts — existing pattern to replicate
let warnedPassword = false;  // module-level guard for one-time warning

const password =
  process.env.LEGATE_SERVER_PASSWORD ??        // NEW: prefer LEGATE_*
  (() => {
    const old = process.env.PREFECT_SERVER_PASSWORD;  // DEPRECATED
    if (old && !warnedPassword) {
      console.error('[Legate] PREFECT_SERVER_PASSWORD is deprecated, use LEGATE_SERVER_PASSWORD');
      warnedPassword = true;
    }
    return old;
  })() ??
  (() => {
    const old = process.env.OPENCODE_SERVER_PASSWORD;  // STILL SUPPORTED: existing chain
    if (old && !warnedPassword) {
      console.error('[Legate] OPENCODE_SERVER_PASSWORD is deprecated, use LEGATE_SERVER_PASSWORD');
      warnedPassword = true;
    }
    return old;
  })();
```

**Critical decision:** The existing `OPENCODE_*` fallback chain must be preserved (not removed). Users may still be on `OPENCODE_*` vars. The chain becomes: `LEGATE_*` (preferred) → `PREFECT_*` (deprecated, warn) → `OPENCODE_*` (deprecated, warn).

However, note that `PREFECT_AUTOSTART_TIMEOUT_MS` and `PREFECT_SESSION_TTL_MS` have NO existing `OPENCODE_*` fallback — they only need the `LEGATE_*` → `PREFECT_*` (warn) chain added.

### Anti-Patterns to Avoid

- **Blind global search-replace without case sensitivity:** `Prefect` (capitalized) appears in comments and user-facing messages; must be renamed to `Legate` (capitalized). `PREFECT` (all-caps) renames to `LEGATE`. `prefect_` (tool names) renames to `legate_`. Three patterns, three replacement rules.
- **Changing `~/.config/prefect/` path:** Explicitly out of scope. Changing it would corrupt the existing `sessions.json` and `servers.json` that users depend on.
- **Forgetting `warnedPassword = false` in `_resetWarnFlags()`:** The `_resetWarnFlags()` internal test helper in auth.ts must also reset any new warning flags added for PREFECT_ deprecation.
- **Missing the `McpServer({ name: 'prefect' })` line:** This is line 94 of index.ts. It controls what namespace Claude Code uses internally. Must become `'legate'`.
- **Missing the `.mcp.json` key inside `cli.ts`:** The `legate init` command writes `mcpServers.legate` to `.mcp.json`. If unchanged, users who run `legate init` would get a `prefect` key instead of `legate`.
- **Missing `install-command` file path:** The command file `~/.claude/commands/prefect-update.md` must become `~/.claude/commands/legate-update.md`, and the `uninstall-command` handler must delete the new path.
- **Not adding the migration note to README:** Users with `PREFECT_*` vars in shell profiles or `.mcp.json` env blocks need explicit guidance.

## Common Pitfalls

### Pitfall 1: Three-Tier Fallback Chain Complexity
**What goes wrong:** Adding `LEGATE_*` → `PREFECT_*` layer without preserving the existing `PREFECT_*` → `OPENCODE_*` layer, breaking users on the old deprecated vars.
**Why it happens:** The refactor looks like a simple swap but is actually an extension of an existing chain.
**How to avoid:** The final chain is `LEGATE_*` (preferred) → `PREFECT_*` (warn once) → `OPENCODE_*` (warn once for vars that had it). For vars without an OPENCODE_ fallback (`TIMEOUT_MS`, `AUTOSTART_TIMEOUT_MS`, `SESSION_TTL_MS`), only the two-tier chain applies.
**Warning signs:** Test fails because a deprecated env var doesn't trigger a warning, or triggers two warnings.

### Pitfall 2: Test Files Reference Old Env Var Names
**What goes wrong:** Tests in `auth.test.ts`, `autostart.test.ts`, `sessions.test.ts` set `PREFECT_*` env vars to test behavior. After rename, these tests would test the **deprecated** fallback path instead of the primary path.
**Why it happens:** Tests are coupled to the env var names they're testing.
**How to avoid:** Update test files in the same PR. Tests should use `LEGATE_*` vars to test primary behavior, and add new tests for the deprecation warning.
**Warning signs:** Tests pass but they're actually testing the deprecated path silently.

### Pitfall 3: `_resetWarnFlags()` Not Updated
**What goes wrong:** The `auth.ts` test helper `_resetWarnFlags()` resets `warnedPassword` and `warnedUsername`. After adding new warning flags for PREFECT_ deprecation, the helper must also reset the new flags, or deprecation warning tests will interfere with each other.
**Why it happens:** Helper function is easy to forget when adding new module-level state.
**How to avoid:** When adding `warnedPrefectPassword` module-level var, immediately also update `_resetWarnFlags()` to include it.

### Pitfall 4: `.mcp.json` Server Key Not Updated
**What goes wrong:** `legate init` still writes `mcpServers.prefect` instead of `mcpServers.legate`. Users who run `legate init` after upgrade get a stale key.
**Why it happens:** The key is a plain string in cli.ts, easy to miss in a mass rename.
**How to avoid:** Verify cli.ts `init` subcommand case: `servers.legate = LEGATE_ENTRY` and the fresh-create path uses `{ mcpServers: { legate: LEGATE_ENTRY } }`.

### Pitfall 5: Documentation Tool Name References in Inline Code Examples
**What goes wrong:** README and uat-v2.md have extensive inline code examples using `prefect_create_session(...)` etc. A partial replace leaves some examples inconsistent.
**Why it happens:** Code examples in markdown use backtick formatting and may span multiple lines.
**How to avoid:** After replace, do a verification grep for remaining `prefect_` strings in doc files. Also check that `prefect-mcp` (binary) and `prefect add-server` (CLI command) references are updated.

### Pitfall 6: Stale Build
**What goes wrong:** Running `npm test` without rebuilding after source changes; tests run against old compiled JS.
**Why it happens:** The `npm test` script runs `tsc` first, but running `node --test build/*.test.js` directly would skip compilation.
**How to avoid:** Always use `npm test` (not direct `node --test`). The script is `tsc && node --test ...`.
