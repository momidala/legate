## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process ↔ user home directory | `installSkillCards` writes to `~/.claude/commands/` (user-owned) using `homedir()` — no privilege escalation. `handleUninstallCommand` deletes only those two exact filenames; no recursive deletion. |
| process ↔ registry file | `buildWorkersSection` reads `~/.config/legate/servers.json` via `readRegistry()`, which already handles ENOENT and JSON-parse errors safely. |
| npm lifecycle ↔ cli | `postinstall` invokes `legate install-command` with `npm_config_global=true`. Failure modes (mkdir/write errors) exit 0 with stderr warning so npm install never blocks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04 | Tampering | path traversal in `destDir` argument to `installSkillCards` | mitigate | `destDir` is always constructed inside cli.ts as `join(homedir(), '.claude', 'commands')` — never accepts user input. Test contract enforces this (callers in `handleInstallCommand` and the `init` case use the homedir-rooted constant). |
| T-06-05 | Tampering | `handleUninstallCommand` recursive deletion of user state | mitigate | `rmSync` calls target exact filenames (`legate.md`, `legate-update.md`) joined to a homedir-rooted dir; `{ force: true }` only suppresses ENOENT, it does NOT enable recursive deletion. No `{ recursive: true }` on rmSync. |
| T-06-06 | Denial of Service | mkdir / writeFile failure blocks npm install | accept (mitigated) | Existing pattern (Phase 2 D-07): catch-branch warns to stderr and exits 0 — never blocks npm install. Plan 02 preserves this. New warning wording `Warning: legate commands not installed —` is asserted by test. |
| T-06-07 | Information Disclosure | servers.json contents written into legate.md | accept | servers.json content (name, host, port, providerID, modelID, maxSessions) is non-sensitive infrastructure metadata the user already documents in CLAUDE.md via `updateClaudemdWorkers`. Same exposure surface; no new sensitive fields added. |
| T-06-08 | Elevation of Privilege | overwriting arbitrary `~/.claude/commands/*.md` | mitigate | `writeFileSync` targets only the two named files (`legate.md`, `legate-update.md`). It cannot write outside `~/.claude/commands/` because the path is constructed from `homedir()` + `.claude/commands` + literal filename. No user-input segment in the path. |
</threat_model>
